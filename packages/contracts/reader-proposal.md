# Reader contract for Antigravity review

The reader at `/[locale]/read`, picker at `/[locale]/read/books`, and dashboard at `/[locale]/today` currently consume fixtures and browser-local reading positions. These proposed operations follow the architecture routes. Fastify currently publishes only `GET /health`. Connect the screens after Antigravity accepts the contract and the owner approves a content version for publication.

| Method and resource                                                     | Request and response                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GET `/v1/editions?lang=&canon=`                                         | Return `{translations: Translation[]}` from the reader-visible registry. Each result carries its source, attribution, licence, language, canon and content version. An empty catalogue is valid.                                                                                                                       |
| GET `/v1/canons/{id}/books?lang=&edition=&version=`                     | Return `{edition, version, books: ReaderBook[]}` in that edition's book order. Supply the language of the returned name when a localized name falls back. Chapter labels are edition-local. DRA includes its seven additional books.                                                                                   |
| GET `/v1/editions/{id}/chapters/{book}.{chapter}?version=&from=&limit=` | Return `ChapterBatch`. First page omits `from`. Subsequent pages use the opaque `nextFrom` bound to edition, version, book, chapter and last row ordinal. An exhausted page returns null. Default 4 rows, explicit limits 1–100. The UI currently requests batches of 5 and can send its preference.                   |
| GET and PUT `/v1/me/position`                                           | Authenticated, private, no-store. PUT accepts edition, version, book, chapter, source label and scroll fraction (0–1). The server checks the published version and label, assigns updatedAt and returns the saved ReadingPosition. GET returns that object or 204 for a new account. Anonymous resume stays on-device. |

### Antigravity's browser-facing routes

Codex accepts the four browser-facing resource names in Antigravity's handoff at `7ca0d22`. The table above describes the service operations. The following mapping can be implemented in a single transport adapter when the reader API is authorized. [Antigravity's handoff](../../docs/UI_TO_CODEX_API_CONTRACTS.md)

| Browser resource                | Service operation and adapter                                                                                                                                                                                                                                                                                            |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/v1/editions`          | Use the editions operation and map translations to the UI's `editions` envelope, with attribution, version and evidence. Return only reader-visible editions. Comparative eligibility requires reviewed mappings.                                                                                                        |
| `GET /api/v1/bible/books`       | Resolve `editionId` to its canon and version. Map locale, ordinal to order, and return books and chapter counts for that edition. Support 73 DRA books.                                                                                                                                                                  |
| `GET /api/v1/bible/text`        | Resolve `editionId, bookId, chapter` to the chapter operation. Accept explicit `batchSize` (UI default 5). Return `verses` and `pagination` with a version-bound continuation. Preserve `label` and `ordinal`; numeric-only verse numbers, range bounds and computed next-verse numbers cannot address every source row. |
| `GET/PUT /api/v1/user/position` | Map to the authenticated position operation. Carry the exact source label and checksum. Anonymous readers continue using local storage.                                                                                                                                                                                  |

Use `eng-web`, `eng-bsb`, `eng-dra`, `tel-irv` and `hin-irv` as edition identities. The launch catalogue comes exclusively from the server. A bridge such as `3-4` is one row. Preserve its label on screen and in positions. Count rows for pagination. Place annotations by source sequence and preceding label, including null before the first verse. The eventual chapter handler should send each annotation once across a sequence of pages and include attribution on every page. API data has no cross-translation alignment key until OC-05.

For example, a synthetic position is `{"edition":"tel-irv","version":"<returned checksum>","book":"DEU","chapter":"1","label":"3-4","scrollFraction":0.25,"updatedAt":"2026-11-23T12:00:00Z"}`. The current UI stores a numeric verse and a 0–100 percentage. Its adapter must convert percentages, accept string labels and avoid guessing a bridge or an equivalent label after changing editions. The current UI's language and testament unions also need to accommodate Hindi and deuterocanonical coverage.

Return 404 for unavailable editions, versions or chapters, 400 for malformed parameters, 409 for a stale continuation on an otherwise available edition and 401 for anonymous sync. Use the action fixed by the route. Content-bearing caches need an independent cache grant and revocation handling before activation. Antigravity should confirm the string-label, version, pagination, annotation-anchor and position shapes against the two reader screens before switching from fixtures. [Wire types](reader.ts)
